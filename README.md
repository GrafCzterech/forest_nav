# forest_nav

Navigation task, defined for a forest environment generated by
[`forest_gen`](https://github.com/GrafCzterech/forest_gen),
utilizing [STRIPE-kit](https://github.com/GrafCzterech/STRIPE-kit). This is
where the forest generation hyperparameters
are defined, and the training script is located.

## Installation

Naturally you are going to need to have STRIPE-kit, forest_gen and Isaac Lab
installed. For the former, best you simply install it using pip:

```bash
pip install stripe-kit forest_gen
```
Unfortunatelly assets required for forest_gen need to be downloaded directly
from GitHub. After downloading them inside catalogue of your choosing you wil
need to specify that catalogue as "asset path" string argument of ForestGenSpec
inside forest_nav/src/simulation.py file.

Installing Isaac Lab is a bit more involved, you best follow instructions
in the [`stripe_kit` documentation](https://grafczterech.github.io/STRIPE-kit/installation.html).

## Scripts

- `sim.sh`: Script to simulate the environment generated by `forest_gen`.
- `train.sh`: Script to train the navigation task using STRIPE-kit.

## Architecture

This repository acts as the bridge, tying all the components of a project
together. STRIPE-kit provides the necessary tools for environment generation
and task definition, `forest_gen` actually implements the forest generation
logics, while this repository defines the navigation task and provides
scripts to launch the simulation and training processes.

This is entirely out of convenience, there's absolutely nothing stopping you
from having both environment generation and task definition in the same
repository. At the end of the day, you just need to somewhere define
the environment and task. STRIPE-kit makes both easier and simpler.

For more details on the architecture, please refer to the related
[`stripe_kit` documentation](https://grafczterech.github.io/STRIPE-kit/architecture.html).

## Tests

Unfortunately, unit testing with Isaac Lab is a bit tricky. One would need to
have a test machine capable of running Isaac Lab simulation, because simply
importing from the `isaaclab` module requires a running simulation.

As such we have resorted to manual testing. Yikes, we know. However, such is
life. You can preview the test scenarios we do regularly [here](./doc/tests.md).
